# SK바이오팜 가족 AI Creation Lab 커리큘럼 상세 v1

## 0. 한 줄 정의

> **부모와 아이가 한 팀이 되어 AI에게 목표를 설명하고, 결과를 검증하고, 반복 개선하여 하나의 playable product를 완성하는 4시간 프리미엄 가족 AI 창작 랩.**

이 수업은 게임 제작 수업이 아니다. 게임은 7 AI Native Assets를 훈련하고 관찰하기 위한 프로젝트 매개다. 핵심 산출물은 `완성된 게임 + 7 Assets 성장 증거 + 다음 프로젝트 제안`이다.



## 봉호 커리큘럼 적용 상태

현재 v1은 봉호님의 기존 커리큘럼을 **부분 적용**한 상태다. 다음 원칙은 반영되어 있다.

- `평소 = 지시받는 사람 → 오늘은 내가 AI를 지시하는 사람 → 내 것을 직접 만들어낸다 → 증거를 손에 쥐고 돌아간다`라는 핵심 경험 구조
- 5블록 흐름: 도입 → 탐색 → 첫 시도 → 개선 → 공유
- 아동 스킨의 `AI 지휘관` 프레임
- 자기 캐릭터/세계/게임을 만들고 QR/결과물로 가져가는 구조
- 16원칙 중 질문, 입력, 만족 유예, 수행/위임, 감탄, 소격 계열

다만 v1 초안은 SK바이오팜 일정/분반/Studio 요구사항을 우선 정리하느라, 봉호님 원본의 핵심 표현을 충분히 전면화하지 못했다. 이후 버전에서는 아래 3개를 최상위 구조로 고정한다.

1. **AI 지휘관 서사**: 아이는 수동적 수강생이 아니라 AI에게 명령하는 사람이다.
2. **블록3가 핵심**: 첫 결과가 마음과 다를 때, 더 정확한 질문으로 결과를 바꾸는 경험이 수업의 중심이다.
3. **증거 수여**: 결과물 URL/QR/발표 카드/성장 리포트로 “내가 만든 것”을 손에 쥐고 돌아간다.

## 결정 업데이트 — 봉호 커리큘럼을 HypeProof Studio로 구현

SK바이오팜 가족 AI 게임 창작 수업은 봉호 커리큘럼을 본체로 두고 [[hypeproof-studio]]로 구현한다. 범용툴을 그대로 쓰는 방식이 아니라, Studio 안에 [[hypeproof-studio-game-skillpack-v1]]을 깔아 게임 제작에 특화된 스킬·룰·프롬프트를 제공한다.

핵심 이유:

- 초3~초6 가족 수업에서는 범용 코딩툴보다 guided environment가 완성률을 높인다.
- HypeProof Studio가 있어야 수업 흐름, 안전장치, 결과물 저장, 성장 리포트 데이터 수집을 통제할 수 있다.
- 상품의 본질은 툴 사용법이 아니라 7 AI Native Assets 훈련이다.
- 게임 제작 자유도가 높기 때문에 사전 룰/프롬프트 scaffolding이 필수다.

## 5. 블록별 상세 스크립트

### 블록 1. 오프닝 — AI를 지휘한다

목표: 아이와 부모가 “코딩을 배우는 시간”이 아니라 “AI를 지휘해 결과물을 만드는 시간”으로 관점을 바꾼다.

진행 메시지:

> 오늘 중요한 건 코드를 외우는 게 아닙니다. AI에게 목표를 잘 설명하고, 나온 결과를 보고, 더 좋게 고치는 힘입니다. 오늘 여러분은 AI 사용자라기보다 작은 프로젝트의 지휘관입니다.

활동:

- “재밌는 게임 만들어줘”와 “초등학생이 3분 안에 플레이할 수 있는 별 모으기 게임을 만들어줘” 비교
- 좋은 요청의 구성: 목표, 대상, 규칙, 분위기, 제한조건
- 부모에게 역할 안내: 대신 해주지 말고 질문으로 아이의 생각을 꺼낸다

### 블록 2. 목표 정하기

목표: 게임이 어떤 경험을 주는지 먼저 정한다.

프롬프트 카드:

- 플레이어가 어떤 기분을 느끼면 좋을까?
- 게임에서 무엇을 모으거나 해결할까?
- 너무 어렵거나 무서운 요소는 무엇을 피할까?
- 3분 안에 친구가 이해할 수 있으려면 어떤 규칙이어야 할까?

산출물:

```text
내 게임은 [누가] [무엇을 하며] [어떤 기분]을 느끼는 게임이다.
```

### 블록 3. 세계/캐릭터/규칙 설계

목표: AI가 이해할 수 있는 충분한 맥락을 설계한다.

기획 카드 항목:

| 항목 | 질문 |
|---|---|
| 캐릭터 | 주인공은 누구인가? 어떤 모습인가? |
| 세계 | 어디에서 벌어지는 일인가? |
| 목표 | 플레이어가 무엇을 하면 성공인가? |
| 방해물 | 무엇이 어렵게 만드는가? |
| 보상 | 성공하면 무엇이 달라지는가? |
| 금지 | 넣지 말아야 할 것은 무엇인가? |

A반 추가 항목:

- 점수 규칙
- 난이도 변화
- 실패/재도전 방식
- 플레이 시간이 3분을 넘지 않게 하는 방법

B반 조정 항목:

- 캐릭터 이름
- 좋아하는 색/장소
- 모으고 싶은 물건
- 친구에게 보여주고 싶은 장면

### 블록 4. 역할 나누기

목표: AI에게 무작정 맡기지 않고, 사람과 AI의 역할 경계를 정한다.

역할 분담 예시:

| 역할 | 담당 |
|---|---|
| 게임 아이디어 | 아이 |
| 조건을 더 구체화하는 질문 | 부모/코치 |
| 코드/화면 생성 | AI |
| 재미있는지 판단 | 아이 |
| 안전하고 적절한지 확인 | 부모/코치 |
| 다음 수정 요청 | 아이 + 부모 |

Delegation Judgment 선언:

> AI는 만들어줄 수 있지만, 무엇이 좋은지는 우리가 판단한다.

### 블록 5. AI로 1차 제작

목표: 빠르게 V1을 만들어 첫 결과물을 본다.

운영 원칙:

- 1차 결과는 완성품이 아니라 테스트 재료라고 설명한다.
- HypeProof Studio의 템플릿/프롬프트 카드로 시작해 실패율을 낮춘다.
- 코치가 대신 완성하지 않는다. 막힌 경우 질문 또는 선택지를 준다.

V1 생성 프롬프트 구조:

```text
역할: 너는 어린이를 위한 간단한 웹 게임 제작자다.
목표: [아이의 게임 목표 문장]
대상: 초등학생이 3분 안에 이해하고 플레이할 수 있어야 한다.
맥락: [캐릭터/세계/규칙]
제약: 무섭거나 폭력적인 요소 없이 밝고 안전한 게임으로 만든다.
출력: 바로 실행 가능한 단일 HTML 게임 또는 HypeProof Studio 템플릿에 맞는 게임 코드.
```

### 블록 6. 플레이 검증

목표: 결과물을 눈으로만 보지 않고 직접 플레이하며 고칠 점을 찾는다.

검증 체크리스트:

- 시작하자마자 무엇을 해야 하는지 알 수 있는가?
- 30초 안에 재미있는 일이 생기는가?
- 너무 어렵거나 너무 쉬운가?
- 캐릭터/세계가 내가 말한 것과 맞는가?
- 친구에게 보여주고 싶은 장면이 있는가?
- 이상한 문구나 부적절한 내용은 없는가?

### 블록 7. 개선 루프

목표: “한 번 생성하고 끝”이 아니라 반복 개선을 몸으로 경험한다.

수정 요청 패턴:

| 문제 | 수정 요청 예시 |
|---|---|
| 너무 어려움 | “초등학생이 처음 해도 성공할 수 있게 난이도를 낮춰줘.” |
| 재미가 약함 | “30초마다 새로운 보상이 나오게 해줘.” |
| 목표가 불명확함 | “화면 위에 오늘의 미션을 크게 보여줘.” |
| 내 아이디어와 다름 | “주인공을 고양이 마법사로 바꾸고 배경은 바닷속으로 바꿔줘.” |
| 디자인이 아쉬움 | “더 밝고 귀여운 색감으로 바꾸고 버튼을 크게 해줘.” |

### 블록 8. 발표와 자산화

목표: 결과물을 자기 프로젝트로 설명하고, 다음 버전으로 이어지게 한다.

발표 카드:

```text
게임 이름:
누가 플레이하나요:
플레이어가 해야 할 일:
처음 결과에서 마음에 안 들었던 점:
내가 고친 점:
다음 버전에 넣고 싶은 것:
```

## 8. 코치 운영 원칙

- 대신 입력하지 않는다. 질문으로 아이의 생각을 꺼낸다.
- 정답을 주지 않는다. 선택지를 제시한다.
- 게임 완성보다 “아이의 판단이 남는 것”을 우선한다.
- 부모가 과개입하면 역할을 재조정한다.
- AI 오류는 실패가 아니라 검증/개선의 재료로 전환한다.

코치 명칭은 `Assistant Instructor`보다 `AI Builder Coach` 또는 `Family Project Coach`를 사용한다.
