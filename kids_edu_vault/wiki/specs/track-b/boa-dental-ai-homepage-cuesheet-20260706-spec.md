# 보아치과 AI 홈페이지 실습 큐시트 2026-07-06

## 운영 방식

- 메인강사는 보아치과 홈페이지를 만든다고 가정하고 스크린을 띄워 단계별로 진행한다.
- 수강생은 같은 단계에서 각자 병원 홈페이지를 만든다.
- 보조강사는 중간중간 막히는 부분을 현장에서 지원한다.
- 수강생은 치과원장 11명, 운영진은 메인강사 1명과 보조강사 5명으로 운영한다.
- 보조강사 1명당 수강생 2명을 담당하고, 11번째 수강생은 3인 포드로 배치한다.

## 최종 결과물

1. 홈페이지
2. 배포 URL
3. GitHub 저장소
4. `agent.md` 인수인계 문서

## 사전 준비물

1. BOA 치과 완성 데모
2. HypeProof Studio 등록 플로우: 설치, 학생 등록, 토큰 발급, 토큰 입력, 채팅 테스트 5분 컷
3. 배포 스킬: Cloudflare, GitHub Pages
4. 디자인 스킬
5. Playwright MCP

## 진행 큐시트

### 19:00-19:10 완성 데모

- BOA 치과 완성 홈페이지 시연
- BOA 치과 제작 채팅 로그 시연
- 오늘 만들 결과물 안내: 홈페이지, 배포 URL, GitHub 저장소, `agent.md`
- 전체 흐름 안내: URL 초안 → 병원 컨텍스트 → 큐레이션 → 루브릭 → 될 때까지 자동 개선 → 최종안 고정

### 19:10-19:30 세팅

- HypeProof Studio 설치
- 학생 등록
- 토큰 입력
- 채팅 테스트
- GitHub 가입
- GitHub 소개: 코드 저장, 홈페이지 배포, AI agent 인수인계
- 2인 1조 배치

### 19:30-19:45 Reference First

- 보아치과 홈페이지 제작 화면 기준으로 실습 시작
- 참고 홈페이지 URL만 넣고 1차 초안 생성
- 참고 URL이 없는 경우 BOA 치과 주소 사용
- 본인 치과 홈페이지 1차 초안 생성

핵심: URL만 줘도 AI는 빠르게 초안을 만든다. 결과는 참고 사이트의 분위기를 따라가지만, 우리 병원의 맥락은 아직 부족하다.

### 19:45-20:05 Context Engineering

- 1차 초안에 병원 컨텍스트 추가
- URL만 넣은 결과와 컨텍스트를 자세히 넣은 결과 비교
- 본인 치과 컨텍스트 입력: 어필 포인트, 밀고 싶은 진료, 주요 환자층, 병원의 톤, 첫 화면 인상, 빼고 싶은 표현
- 2차 초안 생성
- 보조강사가 좋은 컨텍스트 사례 2-3개 수집
- best-case 큐레이션: *봉호님 작성 예정

핵심: 대충 URL만 넣었을 때와 병원 컨텍스트를 자세히 알려줬을 때의 결과 차이를 체감한다.

### 20:05-20:35 Loop Engineering

- 홈페이지 평가 루브릭 작성
- Playwright MCP로 화면 검사
- 루브릭 미달 항목 확인
- AI에게 수정 지시
- 다시 검사
- 루브릭을 만족할 때까지 검사와 수정을 반복
- 보조강사가 좋은 루브릭/자동 개선 사례 2-3개 수집
- best-case 큐레이션: *봉호님 작성 예정

핵심: 루브릭을 정의하고, 그 기준을 만족할 때까지 AI가 계속 검사하고 고치게 한다. 핵심은 될 때까지 반복시키는 것이다.

### 20:35-20:58 최종안 고정

- 홈페이지 최종안 저장
- 배포 URL 생성
- GitHub 저장소에 지금까지 작업한 내용 업로드
- `agent.md` 인수인계 문서 업로드

### 20:58-21:00 결과물 확인

- 홈페이지 확인
- 배포 URL 확인
- GitHub 저장소 확인
- `agent.md` 확인

## 마무리 메시지
