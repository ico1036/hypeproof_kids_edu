# 보아치과 강의 v2 — 잘 만든 홈페이지 겉껍데기 카피하기

## 0. 무엇이 바뀌나 (v1 → v2)

v1(detail-v1)의 **핵심 가치는 그대로 복사**하고, **겉껍데기(활동의 표면)만 교체**한다.

| 레이어 | v1 (detail-v1) | v2 (이번 변경) |
|---|---|---|
| 표면 활동 (껍데기) | 강사가 만든 **빈 샘플 치과 홈페이지**를 같은 프롬프트로 생성 | **실제로 잘 만든 홈페이지 1개를 골라 그 겉모습(레이아웃·디자인·카피 톤)을 AI로 클론** |
| 목표 이미지 | 추상적(머릿속 샘플) | 구체적(눈앞의 실재 사이트 = 정답지) |
| 진행 형식 | 따라 만들기 | 따라 만들기 + **해커톤형 베스트 선정** |
| 유지되는 핵심 | 요리교실 모델 / 공개 URL까지가 완성 / 7 Assets 체득 / 의료광고 검증 / 자기병원 전환 | **전부 동일하게 유지** |

## 1. 생각의 과정 (왜 이렇게 바꾸는가)

1. **v1의 약점**: "샘플을 만들어 보세요"는 정답지가 없다. 초심자는 "이게 잘 된 건지" 판단 기준이 없어 Taste/Verification 자산이 약하게 자극된다.
2. **카피 모델의 강점**: 잘 만든 실재 사이트가 **눈앞의 정답지(target)** 가 된다. "저거랑 똑같이 만들어줘"는 프롬프트로도 훨씬 강력하다 — 타겟 스크린샷/URL을 맥락으로 직접 주입할 수 있다(Context Design 자산이 자연스럽게 강해짐).
3. **해커톤 호환**: 6/15 회의의 "잘 만든 홈페이지 1개 골라 따라 만들기 → 베스트 선정"과 정확히 맞물린다. 같은 타겟을 모두가 클론하니 결과물 비교·심사가 공정해진다.
4. **반드시 지켜야 할 가드레일 (저작권/디자인 도용)**: 실재 사이트를 **그대로 베끼는 것이 목적이 아니다.** "잘 된 구조·레이아웃·정보 위계를 레퍼런스로 학습 → 내 콘텐츠로 재구성"이 원칙. 로고/사진/문구를 그대로 복제하지 않는다. 이 지점이 오히려 **Verification·Taste·의료광고 자산을 가르치는 최고의 교보재**가 된다.
5. **결론**: 핵심 가치(요리교실·공개 URL·7 Assets·검증·전환)는 1mm도 손대지 않고, 출발점만 "빈 샘플 생성"에서 "정답지 클론"으로 바꾼다.

## 2. 타겟 사이트 선정 기준 (강사 사전 준비)

- 치과/병원/클리닉 계열 중 **레이아웃·정보 위계가 명확하고 모던한** 공개 사이트 1개.
- 너무 화려한 인터랙션(과한 애니메이션)은 제외 — 3시간 내 재현 가능해야 함.
- 강사는 타겟의 **풀페이지 스크린샷(데스크탑+모바일)** 과 섹션 구조 분해표를 미리 준비한다.
- 저작권 안전을 위해 **레퍼런스는 1개로 고정**하고, "구조만 차용/콘텐츠는 데모 자산으로 교체"를 명문화한다.

## 3. 3.5시간 플로우

| 시간 | 블록 | 목표 | 산출물 |
|---|---|---|---|
| 0:00–0:15 | 정답지 공개 | 오늘 클론할 타겟 사이트와 최종 URL을 먼저 보여줌 | 타겟 이미지 |
| 0:15–0:35 | 구조 분해 | 타겟을 Hero/진료과목/의료진/위치/CTA로 쪼개 보기 | 섹션 분해표 |
| 0:35–1:15 | 1차 클론 | 타겟 스크린샷을 맥락으로 주입 → 겉껍데기 V1 생성 | 클론 V1 |
| 1:15–1:45 | 콘텐츠 교체 | 로고·사진·문구를 데모 자산으로 교체(도용 금지 실습) | V2 |
| 1:45–2:10 | AI 미니 모듈 | 이미지 맥락 주입·부분 수정·토큰 설명 | 수정 프롬프트 카드 |
| 2:10–2:40 | 디테일 튜닝 | 색/폰트/간격을 타겟에 근접 + 내 톤으로 변형 | V3 |
| 2:40–3:10 | 배포 | Vercel/Cloudflare 공개 URL 생성 | 공개 URL |
| 3:10–3:30 | 해커톤 심사 | 팀별 결과물 비교 → 베스트 선정(완성도/검증/Taste 기준) | 베스트 |
| 3:30–3:40 | 의료광고 검증 | 게시 전 검수 원칙 | 검증 체크리스트 |

## 4. 핵심 프롬프트 패턴 (v2 신규)

```text
[첨부: 타겟 사이트 데스크탑/모바일 스크린샷]
역할: 시니어 웹 디자이너 겸 프론트엔드 개발자.
목표: 첨부한 사이트의 "레이아웃·정보 위계·디자인 톤"을 참고해
      동등한 품질의 치과 홈페이지 골격을 만든다.
제약: 로고·사진·문구는 복제하지 말고 자리표시자/데모 자산으로 둔다.
      의료광고법상 과장 표현 금지.
출력: 배포 가능하고 비개발자가 수정하기 쉬운 구조.
```

> [!key-insight] v2의 교육적 정수
> "남의 좋은 결과를 보고 → 구조를 읽고 → 내 것으로 재구성"은 실무에서 AI를 쓰는 가장 현실적인 루프다. 베끼기가 아니라 **벤치마킹을 가르친다.**

## 5. 7 Assets 매핑 (v1 대비 강화점)

| Asset | v2에서 강해지는 지점 |
|---|---|
| Context Design | 타겟 스크린샷/URL을 맥락으로 주입하는 경험이 핵심 활동이 됨 |
| Taste | "정답지와 내 결과물 비교"가 상시 일어남 |
| Verification | 도용/의료광고 가드레일이 자연스러운 검증 훈련이 됨 |
| 나머지(Intent/Iteration/Delegation/Ownership) | v1과 동일 유지 |

## 6. 오픈 이슈

- 타겟 사이트 1개 최종 확정(저작권 안전 + 재현 난이도)
- 클론 시 "이미지 맥락 주입"을 어떤 도구가 지원하는가 → [[hypeproof-studio]] 기술 체크 필요(아래 별도 문서/메시지)
- 해커톤 심사 기준표 확정
- 3 vs 3.5 vs 4시간
