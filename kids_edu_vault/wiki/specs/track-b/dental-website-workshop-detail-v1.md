# 보아치과 강의용 AI 웹사이트 만들기 상세 v1

## 0. 한 줄 정의

> **치과 비전문가가 샘플 치과 홈페이지를 요리교실처럼 그대로 따라 만들고, 세미나 끝에는 실제 접속 가능한 공개 URL을 얻는 AI Native 제작 실습.**

이 강의는 [[claude-code]] 사용법 강의가 아니다. 홈페이지라는 구체 산출물을 통해 Intent Clarity, Context Design, Iteration, Verification, Taste, Ownership을 체험하게 하는 HypeProof식 AI Native 제작 강의다.

## 1. 전략 판단: Tool은 범용툴, Product는 HypeProof Method

### v1 운영 권장안

| 레이어 | 선택 | 이유 |
|---|---|---|
| 실제 제작 엔진 | [[claude-code]] 중심 | 세미나 후에도 참가자가 집에서 다시 쓸 수 있는 검증된 범용툴 |
| 배포 | [[vercel]] 또는 [[cloudflare]] | 무료/저비용 공개 URL 확보 |

| HypeProof Studio | 보조/실험 | 강사용 스킬팩, 체크리스트, 프롬프트 패키지, 사후 리포트 도구 |

## 2. 고객 가치 제안

### 고객의 기존 문제

- 홈페이지 제작/수정이 외주 의존적이다.
- 작은 문구 수정도 업체 요청이 필요하다.
- [[cafe24]]/관리 업체/서버비 등 비용 구조를 정확히 이해하지 못한다.
- 원장/직원이 홈페이지 구조를 이해하지 못해 장기 운영 주도권이 없다.

### 강의의 약속

- 샘플 홈페이지를 그대로 따라 만들며 완주 경험을 보장한다.
- 세미나 끝에는 실제 접속 가능한 URL을 확보한다.
- 집에 돌아가 자기 병원 정보로 바꾸는 절차를 가져간다.
- AI에게 수정 요청하는 법을 익혀 작은 수정은 스스로 처리할 수 있게 한다.

## 3. 운영 원칙

### 3.1 요리교실 모델

하지 않는다:

- “각자 원하는 홈페이지를 만들어보세요”
- 현장에서 각 병원별 요구사항을 전부 커스텀
- 도구 기능 전체 설명
- 개발자식 개념 강의 선행

한다:

- 샘플 치과 홈페이지 1개를 모두가 같은 순서로 따라 만든다.
- 로고, 이미지, 진료과목, 원장 소개, 위치 등 데모 재료는 강사가 준비한다.
- 참가자는 같은 화면과 같은 프롬프트로 진행한다.
- 마지막 30~40분에 자기 병원용으로 바꾸는 방법을 안내한다.

### 3.2 “띄우는 것까지”가 완성

완성 기준은 로컬 미리보기가 아니다.

- 기본 성공: Vercel/Cloudflare 무료 URL 확보
- 확장 성공: Gabia 도메인 연결 흐름 이해
- 후속 성공: 자기 병원 자료로 교체할 수 있는 체크리스트 확보

### 3.3 AI 교육은 양념처럼 삽입

AI 개념은 별도 강의가 아니라 제작 흐름 사이에 짧게 넣는다.

- 토큰: AI가 한 번에 읽고 다루는 재료 단위
- 프롬프트: 역할, 목표, 제약, 예시, 출력 형식
- 수정 요청: 전체 재생성보다 부분 수정
- 검증: 의료/광고 표현은 사람이 최종 판단
- 반복: 첫 결과물은 초안, 수정 대화가 제작 과정

## 5. 상세 블록

### 블록 1. 결과물 미리 보기

목표: 참가자가 “오늘 무엇을 완성하는지”를 즉시 이해한다.

진행 메시지:

> 오늘은 AI 개념을 길게 듣는 시간이 아닙니다. 이 샘플 치과 홈페이지를 그대로 따라 만들고, 마지막에는 실제 URL로 접속되는 결과물을 가져갑니다. 나중에는 같은 방법으로 우리 병원 홈페이지를 바꿀 수 있습니다.

보여줄 것:

- 완성 샘플 홈페이지
- 모바일 화면
- Vercel/Cloudflare 공개 URL
- 수정 전/후 예시

### 블록 2. 계정/재료 확인

강사 준비물:

- 데모 로고
- 데모 병원 이미지 3~5장
- 원장 소개 샘플
- 진료과목 설명 샘플
- 위치/전화/진료시간 샘플
- 예약 CTA 문구 샘플
- 프로젝트 템플릿
- 프롬프트 카드 PDF 또는 노션/웹 문서

참가자 준비물:

- 노트북
- Claude Code 사용 가능 환경
- GitHub 계정 또는 대체 배포 경로
- Vercel/Cloudflare 계정
- Gabia 도메인 구매는 선택/시연으로 처리

> [!risk] 계정 병목
> 계정 생성과 로그인은 현장 최대 병목이다. 가능하면 사전 안내 메일로 계정을 만들게 하고, 현장에는 계정 문제 담당 코치를 둔다.

### 블록 3. 샘플 홈페이지 1차 생성

목표: 모든 참가자가 같은 샘플을 V1으로 생성한다.

기본 프롬프트 구조:

```text
역할: 너는 치과 홈페이지를 만드는 시니어 웹 디자이너이자 프론트엔드 개발자다.
목표: 비개발자가 이해하고 수정할 수 있는 깔끔한 치과 홈페이지를 만든다.
대상: 강남 소재 치과의 신규 환자와 기존 환자.
구성: Hero, 진료 철학, 주요 진료과목, 의료진 소개, 병원 공간, 위치/진료시간, 예약 CTA.
톤: 신뢰감 있고 과장 없는 전문적인 톤.
제약: 의료광고법상 과장될 수 있는 표현은 피하고, 데모 문구임을 명시한다.
출력: 배포 가능한 웹사이트 프로젝트를 생성하고, 수정하기 쉬운 구조로 작성한다.
```

강의 포인트:

- 첫 결과는 완성품이 아니라 수정할 초안이다.
- AI에게 한 번에 완벽한 결과를 기대하지 않는다.
- 좋은 결과는 좋은 맥락과 반복 수정에서 나온다.

### 블록 4. 섹션별 수정

목표: 참가자가 말로 수정 요청을 넣고 결과 변화를 확인한다.

수정 대상:

| 섹션 | 수정 과제 | Asset |
|---|---|---|
| Hero | 첫 문구를 더 신뢰감 있게 바꾸기 | Taste |
| 진료과목 | 과장 없이 설명 수정 | Verification |
| 원장 소개 | 경력 나열보다 진료 철학 중심으로 변경 | Context Design |
| CTA | “예약하기” 버튼 문구와 위치 조정 | Intent Clarity |
| 색상/폰트 | 병원 분위기에 맞게 조정 | Taste |

수정 요청 예시:

```text
Hero 문구가 너무 광고처럼 느껴진다. 과장 없이 신뢰감 있는 톤으로 바꾸고, 첫 방문 환자가 안심할 수 있는 문장으로 수정해줘.
```

```text
진료과목 설명에서 치료 결과를 보장하는 듯한 표현은 빼고, 진료 과정과 상담 중심으로 안전하게 다시 써줘.
```

### 블록 5. AI 미니 모듈

삽입 타이밍: 참가자가 V1을 본 직후.

핵심 메시지:

- AI는 정답 제조기가 아니라 초안 생성 파트너다.
- 좋은 프롬프트는 목적, 맥락, 제약, 예시를 포함한다.
- 수정 요청은 “다시 만들어줘”보다 “어느 부분을 왜 바꿀지”가 중요하다.
- 의료/광고 표현은 AI가 아니라 사람이 책임진다.

## 6. 배포 블록

### 기본 경로: Vercel

- GitHub 연결 또는 CLI/웹 업로드
- 프로젝트 import
- build 설정 확인
- deploy
- 무료 URL 확인

### 대체 경로: Cloudflare Pages

- 프로젝트 업로드 또는 GitHub 연결
- build 설정 확인
- deploy
- 무료 URL 확인

### Gabia 도메인 연결

세미나 내 완전 연결을 보장하지 않는다. DNS 전파 지연 때문이다.

권장 운영:

- 강사는 도메인 연결 과정을 시연한다.
- 참가자는 무료 URL 확보를 기본 성공으로 둔다.
- 도메인 연결은 집에서 따라 하는 체크리스트로 제공한다.

## 8. 의료광고/검증 원칙

강의 중 샘플은 데모이며 실제 게시 전 반드시 원장 또는 책임자가 검수한다.

체크 질문:

- 치료 효과를 보장하는 표현은 없는가?
- “최고”, “유일”, “100%” 같은 과장 표현은 없는가?
- 전후사진/후기/가격 정보가 규정에 맞는가?
- 의료진 경력과 자격 표기가 정확한가?
- 환자가 오해할 수 있는 문구는 없는가?

## 9. HypeProof Studio Dental Website Skill Pack 구상

1차 강의는 Claude Code 중심으로 운영하되, 아래 요소는 Studio 스킬팩으로 축적한다.

| 스킬팩 구성 | 설명 |
|---|---|
| 샘플 홈페이지 템플릿 | 치과 홈페이지 기본 구조 |
| 프롬프트 카드 | 생성/수정/검증/배포 프롬프트 |
| 의료광고 체크리스트 | 위험 표현 검토 |
| 배포 가이드 | Vercel/Cloudflare/Gabia 단계별 안내 |
| 수정 요청 패턴 | Hero/CTA/진료과목/원장소개별 수정 예시 |
| Export | GitHub repo, zip, 프롬프트 로그, 배포 URL |
| 사후 리포트 | 7 Assets 관찰 기반 피드백 |

### 리스크 관리

Studio가 Claude Code를 완전히 대체하면 위험하다. v1에서는 Studio를 “guided wrapper / 교육 OS”로 두고, 결과물은 외부에서도 열리고 수정 가능해야 한다.

필수 조건:

- 결과물 zip 다운로드 가능
- GitHub/Vercel 프로젝트로 이전 가능
- 프롬프트 로그 export 가능
- Studio 없이도 수정 가능한 README 제공
- 집에서 막힐 때 복구 플로우 제공

## 10. 7 Assets 매핑

| Asset | 강의 중 행동 | 증거 |
|---|---|---|
| Intent Clarity | 홈페이지의 목적과 방문자 행동을 정함 | Hero/CTA 수정 이유 |
| Context Design | 병원 정보, 환자 유형, 진료 철학을 AI에게 제공 | 프롬프트 맥락 |
| Delegation Judgment | AI가 만들고 사람이 의료 표현을 검수함 | 검증 체크리스트 |
| Iteration Reflex | V1 → V2 → V3로 수정 | 버전/수정 로그 |
| Verification Reflex | 링크, 문구, 의료광고 리스크 확인 | 테스트/검수 기록 |
| Taste | 병원 톤에 맞게 디자인/문구 선택 | 선택/거절 이유 |
| Ownership | 집에서 자기 병원용으로 바꿀 계획 수립 | 전환 체크리스트 |

## 11. 운영 인력

| 역할 | 담당 업무 |
|---|---|
| Lead Instructor | 전체 흐름, 시연, 핵심 설명 |
| AI Website Coach | 참가자별 Claude Code/수정 요청 지원 |
| Deployment Coach | Vercel/Cloudflare/Gabia 오류 처리 |
| Medical Expression Reviewer | 위험 문구 체크, 검증 원칙 안내 |

소규모 강의라면 Lead 1 + Coach 1~2 + Ops 1로 시작한다.

## 12. 사전 안내 메일 체크리스트

- 의료광고 표현은 실제 게시 전 원장 검수 필수

## 13. 성공 기준

### 현장 성공

- 참가자 80% 이상이 공개 URL을 확보한다.
- 참가자 전원이 샘플 홈페이지 V1 이상을 만든다.
- 최소 1회 이상 자기 판단 기반 수정 요청을 한다.
- 의료광고/검증 체크리스트를 이해한다.

### 제품 성공

- 참가자가 집에서 자기 병원용으로 바꾸는 절차를 이해한다.
- HypeProof가 프롬프트 카드/체크리스트/템플릿을 재사용 가능한 스킬팩으로 확보한다.
- 다음 강의에서 Studio 기반 Dental Website Skill Pack으로 전환할 수 있는 데이터가 쌓인다.
