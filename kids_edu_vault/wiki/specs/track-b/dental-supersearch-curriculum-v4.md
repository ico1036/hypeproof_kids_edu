# 치과 지식 슈퍼서치엔진 해커톤 v4

## 0. 한 줄 정의

> **직원이 치과 지식 슈퍼서치엔진을 만들고, 원장님에게 깨지면서 병원 내부 검색 규칙을 축적하는 해커톤.**

기존 v3의 핵심인 **“원장님은 5분, 직원이 주인공”**은 유지한다.
다만 산출물을 `개인 프롬프트/작은 업무 결과물`에서 `검색 웹앱 + 원장님 검증 로그 + 병원 내부 지식 규칙`으로 바꾼다.

---

## 1. 기존 v3에서 무엇이 바뀌었나

| 항목 | v3 | v4 슈퍼서치엔진 |
|---|---|---|
| 핵심 컨셉 | 원장님 신뢰도 → 직원 자립 | 원장님을 이겨라 → 직원 검색엔진이 깨지며 성장 |
| 직원 역할 | 자기 반복업무 프롬프트 만들기 | 검색스킬/검색엔진 직접 만들기 |
| 원장님 역할 | 오프닝 5분 + 힌트 제공자 | 오프닝 5분 + 최종 보스/검증자 |
| 산출물 | 개인 프롬프트 + 공유 | 검색 웹앱 + 병원 검색 규칙 + 검증 로그 |
| 학습 포인트 | 맥락을 넣으면 AI가 잘함 | 질문 쪼개기, 도구 선택, 출처 필터, 검증, 내부지식화 |
| 사업적 의미 | 체험형 교육 | HYROX형 해커톤으로 SaaS/FDE 내부 솔루션 심기 |

---

## 2. 제품적 포지션

### HYROX 장치

현장에서는 게임처럼 진행한다.

> **“원장님을 이겨라!”**

직원이 검색엔진을 만들고, 원장님에게 들이밀고, 원장님이 웃으면서 깨준다.
깨지는 것이 실패가 아니라 학습의 클라이맥스다.

### SaaS/FDE 장치

그날 깨진 이유는 그냥 지나가지 않는다.

- 어떤 검색어가 부정확했는지
- 어떤 출처를 믿으면 안 되는지
- 어떤 표현은 환자에게 쓰면 안 되는지
- 원장님은 어떤 기준으로 PASS / 더 확인 / 위험을 나누는지

이것들이 앱의 규칙으로 저장된다.
즉 현장 경험은 HYROX이고, 남는 것은 병원 내부 솔루션이다.

## 3. 60분 기본 진행안

### D-10분: 입장 전 준비

v3와 동일하게 진행한다.

- 원장님과 30초 사전 대화
  - “오늘 실제로 AI 쓰시는 사례 하나만 5분 보여주실 수 있으세요?”
  - 설명하지 말고 실행만 요청
- 직원 자리 확인
  - 각자 기기 앞에 앉아 있는지
  - Studio / AI 도구 로그인 완료 여부
- 진행자는 원장님에게 미리 고지
  - “오늘 원장님은 오프닝 5분과 마지막 보스 역할입니다. 중간에는 직원들이 직접 해봐야 합니다.”

---

### 블록 1. 도입 — 원장님이 먼저 보여주기 (5분)

원장님이 실제 AI 사용 사례 하나를 보여준다.

> “저는 이걸 이렇게 씁니다.”

설명보다 시연이 중요하다.

진행자는 시연 후 직원에게만 묻는다.

> **“어떠세요? 해보고 싶으세요?”**

이후 바로 게임 룰을 제시한다.

> **“오늘은 원장님을 이겨볼 겁니다. 여러분이 검색엔진을 만들고, 마지막에 원장님한테 들이밉니다. 틀리면? 더 좋습니다. 그게 우리 병원 검색 규칙이 됩니다.”**

원장님이 계속 설명하려 하면 v3처럼 전환한다.

> “원장님, 이제부터는 직원분들 차례예요. 지켜봐 주세요.”

---

### 블록 2. 탐색 — 검색할 문제 고르기 (10분)

기존 v3의 “내 업무 중 반복하는 것 하나 고르기”를 유지하되, 주제를 `검색 문제`로 바꾼다.

진행자 멘트:

> **“매일 또는 매주 반복해서 궁금해지는 것, 환자가 자주 물어보는 것, 찾아봐야 하는데 검색어가 막히는 것 하나만 고르세요.”**

좋은 검색 문제의 조건:

1. 실제로 병원에서 자주 마주친다.
2. 구글/블로그만 보면 헷갈린다.
3. 원장님에게 최종 확인이 필요하다.
4. 다음에도 비슷하게 재사용될 수 있다.

예시는 막혔을 때만 제시한다.

| 직군 | 검색 문제 예시 |
|---|---|
| 위생사 | 환자가 물어본 주의사항 근거 확인, 설명 전 참고자료 찾기 |
| 코디 | 환자 안내 표현, 예약/상담 전 자주 묻는 질문 근거 확인 |
| 사모님/관리자 | 소모품/장비/프로그램 후보 비교, 직원 교육자료 조사 |
| 원장님 | 출처 신뢰도 기준, 환자에게 쓰면 안 되는 표현 기준 제공 |

중요: 미션카드를 고르게 하지 않는다. 참가자가 자기 문제를 고르게 한다.

---

### 블록 3. 첫 시도 — 슈퍼서치엔진 V1 만들기 (15분)

직원이 Studio에서 자신의 검색엔진 V1을 만든다.

V1에 반드시 들어갈 입력칸:

1. 내가 알고 싶은 것
2. 이 검색이 도와야 하는 결정
3. 피해야 할 것
4. 원장님께 확인해야 할 것

V1에 반드시 들어갈 출력:

1. 검색 질문 5개
2. 쓸 도구/출처 후보
3. 믿을 출처 / 보류할 출처
4. 위험 신호
5. 원장님께 물어볼 질문

진행자 멘트:

> “처음부터 잘 만들려고 하지 마세요. V1은 원장님한테 깨지기 위한 초안입니다.”

원장님은 이 블록에서 개입하지 않는다.
v3 원칙 그대로:

> “원장님, 이 구간은 직원분들이 스스로 해봐야 하는 구간이에요. 말씀 아껴주시면 훨씬 효과가 큽니다.”

---

### 블록 4. 해부 + 원장님을 이겨라 (20분)

직원이 만든 검색엔진 V1을 원장님에게 보여준다.

진행자 멘트:

> **“자, 원장님을 이겨라 시간입니다. 이 검색엔진 결과, 맞나요?”**

원장님은 정답을 길게 써주는 사람이 아니라, 다음 세 가지 중 하나로 판정한다.

| 판정 | 의미 | 앱에 저장되는 것 |
|---|---|---|
| PASS | 일반 안내/내부 참고 가능 | 승인된 출처/표현/검색 방식 |
| 더 확인 | 조건에 따라 달라짐 | 원장님께 물어볼 추가 질문 |
| 위험 | 환자에게 쓰면 안 됨 | 금지 출처/금지 표현/금지 결론 |

진행자는 원장님 피드백을 직원에게 다시 돌려준다.

> “OO씨, 원장님이 방금 깬 포인트가 뭐였죠? 그걸 검색 규칙에 추가해볼게요.”

직원은 직접 수정한다.

수정 예시:

- 검색어가 너무 일반적이었다 → 전문용어/영어 쿼리 추가
- 출처가 광고성 블로그였다 → 학회/대학병원/제조사 우선순위 추가
- AI가 결론을 내렸다 → “원장님께 확인할 질문”으로 바꿈
- 환자에게 불안한 표현이었다 → 환자용 표현 규칙 추가

---

### 블록 5. 저장 + 공유 (10분)

기존 v3의 저장/공유를 유지하되, 저장 대상이 프롬프트가 아니라 검색스킬 패킷이다.

저장 패킷:

1. 검색 목적
2. 검색 질문 템플릿
3. 신뢰 출처 우선순위
4. 걸러낼 출처/표현
5. 원장님 판정 로그
6. 다음에 재사용할 검색 규칙

공유 멘트:

> “각자 만든 검색엔진이 어떤 질문을 잘 파는지 한 마디씩만요.”

원장님 반응 유도:

> “원장님, 이 중에 병원에서 계속 쓸 만한 규칙이 있었나요?”

클로징:

> **“오늘 만든 건 검색 결과가 아닙니다. 우리 병원이 앞으로 뭘 믿고, 뭘 거르고, 언제 원장님께 물어볼지 정한 첫 번째 검색 규칙입니다.”**

## 4. 7 AI Native Assets 강화 버전

슈퍼서치엔진 만들기는 7개 Asset을 전부 쓴다.

| Asset | 검색스킬에서의 의미 | 참가자가 하는 행동 | 앱에 남는 기능 |
|---|---|---|---|
| Intent Clarity | 검색 목적을 결정 문제로 바꾸는 힘 | “무엇을 알고 싶나?”가 아니라 “무슨 결정을 해야 하나?”를 적음 | 검색 목적/성공 기준 입력 |
| Context Design | AI가 오해하지 않게 조건을 설계하는 힘 | 환자군, 상황, 병원 톤, 금지표현, 판단 기준 입력 | Context Pack |
| Delegation Judgment | AI와 원장님의 역할을 나누는 힘 | 검색/요약/비교는 AI, 임상 판단은 원장님으로 분리 | AI 가능/주의/금지 업무 분류 |
| Iteration Reflex | 검색 전략을 계속 고치는 힘 | 검색어, 도구, 출처 필터를 바꿔 V2 생성 | 재검색 버튼/쿼리 변형 |
| Verification Reflex | 출처와 결론을 검증하는 힘 | 공식/학회/논문/제조사/광고글 구분 | 출처 신뢰도 점수/위험 신호 체크 |
| Taste | 표현과 출력 형태를 고르는 힘 | 환자용/내부용/원장님 질문용 표현 분리 | 출력 톤 변환 |
| Ownership | 검색결과를 병원 자산으로 책임지는 힘 | 원장님 피드백을 규칙으로 저장 | 병원 검색 규칙/검증 로그 |

---

## 5. 검색스킬 제작 루프

참가자가 진짜 고민하게 될 지점은 다음이다.

### 1. 질문 쪼개기

- 큰 질문을 검색 가능한 작은 질문으로 분해
- 한국어/영어/전문용어 쿼리 변환
- 결론형 질문과 근거형 질문 구분

예:

- 나쁜 질문: “임플란트 후 운동해도 돼?”
- 좋은 질문:
  - “임플란트 수술 후 운동 제한 기간 guideline”
  - “implant surgery postoperative exercise recommendation”
  - “발치 후 출혈 운동 영향 환자 안내”

### 2. 도구 고르기

| 도구/출처 | 역할 |
|---|---|
| 웹검색 | 넓게 훑기 |
| 학회/대학병원 | 환자 안내 기준 확인 |
| 논문/리뷰 | 근거 확인 |
| 제조사 문서 | 장비/재료/제품 정보 확인 |
| 블로그/유튜브 | 표현 참고. 근거로는 보류 |

### 3. 출처 필터링

걸러낼 것:

- 광고성 블로그
- 제품 판매로 바로 이어지는 글
- 날짜가 오래된 정보
- 출처 없는 단정
- “무조건 가능”, “완전 안전”, “통증 없음” 같은 보장 표현

우선할 것:

- 원장님이 승인한 출처
- 학회/대학병원 자료
- 공식 제품 문서
- 리뷰 논문/가이드라인

### 4. 원장님 질문 만들기

AI가 결론내지 말아야 한다.
애매한 것은 원장님께 물어볼 질문으로 바꾼다.

예:

- “이 표현 환자에게 써도 되나요?”
- “이 출처 우리 병원 기준에 맞나요?”
- “이건 일반 안내로 가능하고, 어떤 경우부터 원장님 확인이 필요한가요?”

### 5. 깨진 이유 반영

원장님에게 깨진 포인트를 앱 규칙으로 저장한다.

- 틀린 검색어
- 믿으면 안 되는 출처
- 우리 병원 금지 표현
- 원장님 확인이 필요한 조건
- 다음 검색 때 먼저 볼 출처

### 6. 재사용 규칙화

다음 검색부터 자동 적용한다.

- 승인 출처 먼저 보기
- 광고성 출처 보류
- 환자용 표현 자동 순화
- 원장님 질문 자동 생성

## 6. 내부 지식으로 남는 것

해커톤이 끝나면 다음 네 가지가 남아야 한다.

1. 우리 병원 표현
   - 환자에게 쓰는 말투
   - 금지어
   - 불안을 줄이는 설명 방식

2. 원장님 판정 기준
   - PASS / 더 확인 / 위험을 나누는 기준
   - 어떤 경우 환자 안내 가능하고, 어떤 경우 원장님 확인이 필요한지

3. 자주 받는 질문
   - 실제 환자가 묻는 질문
   - 직원이 검색하다 막힌 질문
   - 신규 직원이 반복해서 물어볼 질문

4. 신뢰 출처 목록
   - 원장님이 인정하는 학회/대학병원/제조사/문서
   - 보류해야 할 출처 유형

## 7. 고급반: 병원 전용 Obsidian 지식 볼트

초급반이 슈퍼서치엔진 만들기라면, 고급반은 병원 전용 지식 볼트 구축이다.

볼트 구조 예시:

```text
boah-dental-knowledge-vault/
  index.md
  hot.md
  questions/
    임플란트-운동-가능시점.md
    발치후-출혈-문의.md
  reviews/
    원장님-판정-log.md
  sources/
    approved-sources.md
    rejected-sources.md
  style/
    우리병원-표현규칙.md
    환자용-금지표현.md
  templates/
    supersearch-template.md
    patient-explanation-template.md
  rules/
    pass-more-check-risk.md
```

고급반 산출물:

- 질문 노트

## 9. 퍼실리테이터 운영 규칙

v3 규칙을 그대로 유지한다.

| 상황 | 대응 |
|---|---|
| 원장님이 중간에 계속 개입 | “원장님, 지금은 직원들이 검색엔진을 만들어야 해서요. 마지막 보스전에서 깨주세요.” |
| 직원이 질문을 못 고름 | “최근 환자나 동료가 물어봤는데 바로 답하기 애매했던 것 하나만 떠올려보세요.” |
| 직원이 AI 답을 그대로 믿음 | “좋아요. 그럼 이걸 원장님께 물어볼 질문으로 바꿔볼게요.” |
| 원장님이 정답을 길게 설명 | “좋습니다. 그럼 한 줄 규칙으로 바꾸면 뭐라고 저장할까요?” |
| 시간이 부족 | 원장님 판정 1개만 받고 바로 저장 패킷으로 이동 |

## 10. 성공 기준

나쁜 성공:

- “AI 신기하네요”로 끝남
- 원장님이 강의 대부분을 설명함
- 직원이 AI 결과를 그대로 복사함
- 검색 결과만 남고 규칙이 안 남음

진짜 성공:

- 직원이 자기 질문을 검색 가능한 문제로 바꿈
- 검색어/도구/출처 필터를 한 번 이상 수정함
- 원장님에게 한 번 깨짐
- 깨진 이유가 검색 규칙으로 저장됨
- 최소 하나의 병원 내부 지식이 남음

최종 한 줄:

> **게임처럼 들어와서, 병원 지식 시스템을 두고 나간다.**
