# 보아치과 AI 홍보 HYROX — Context Engineering + Loop Engineering

## 0. 현재 정리

이 버전은 내부 설계 해설서를 클라이언트 전달물에서 빼고, "강의"가 아니라 HYROX형 챌린지로 재프레이밍한다. 원장님은 수강자가 아니라 완주자다. 홈페이지 초안은 경기 결과이고, 진짜 남는 것은 원장님이 어떤 맥락을 줬고 어떤 피드백으로 바꿨는지에 대한 기록이다.

클라이언트용 문서에서는 HYROX/헬스장 단어를 직접 쓰지 않고, 같은 디자인/구조 언어를 `AI 홍보 레이스`로 번역한다.

1. **Context Engineering**: 맥락과 생각을 정확히 전달하는 법
2. **Loop Engineering**: 원하는 방향으로 될 때까지 피드백 하며 반복하는 법

실제 예약·상담·지도 연결 같은 운영 설정은 이번 범위에서 제외한다. 원장님 도메인지식으로 틀린 것을 걸러내는 장면은 과정상 자연히 생기지만, 커리큘럼의 주연으로 강조하지 않는다.

## 0.1 2026-07-06 2시간 큐시트 정본

Source: [[boa-dental-ai-homepage-cuesheet-20260706]]

[[boa-dental-ai-homepage-cuesheet-20260706-spec]]는 2시간 외부 공유용 운영 정본이다. 이 정본에서는 HYROX/해커톤/발표/우승자 감성을 빼고, `완성 데모 → 세팅 → Reference First → Context Engineering → Loop Engineering → 최종안 고정`의 큐시트만 남긴다.

운영 방식은 메인강사가 보아치과 홈페이지를 만든다고 가정하고 스크린을 띄워 단계별로 진행하는 구조다. 수강생은 같은 단계에서 각자 병원 홈페이지를 만들고, 보조강사는 중간중간 막히는 부분만 현장에서 지원한다.

최종 결과물은 홈페이지, 배포 URL, GitHub 저장소, `agent.md` 인수인계 문서 4개로 고정한다. Context Engineering은 URL만 넣은 1차 결과와 병원 컨텍스트를 자세히 넣은 2차 결과의 차이를 체감시키고, Loop Engineering은 루브릭을 만족할 때까지 검사와 수정을 반복시키는 것을 핵심으로 둔다.

## 1. 한 줄 정의

> **평소 홈페이지 홍보 방향을 외주 일정과 말투에 맡기던 원장이, 4시간 AI 홍보 HYROX를 완주하며 자기 병원의 맥락을 정확히 설명하고, 원하는 방향이 될 때까지 피드백을 반복해 홈페이지 초안을 직접 바꿔보는 경기형 프로그램.**

봉호 코어의 성인 번역:
```text
평소 = 홈페이지는 내가 못 건드리는 것 (외주 의존)
        ↓
오늘 = 내가 AI를 지시하는 사람
        ↓
내 병원 홈페이지를 직접 만들어낸다
        ↓
내 치과 홍보를 내가 원하는 대로 바꿀 자유도를 손에 쥐고 돌아간다
```

보아치과판 클로징은 부모/아이 강의처럼 "아이의 성장"으로 끝나면 안 된다. 원장이 자기 치과 홍보를 외주 순서와 말투에만 맡기지 않고, 본인이 원하는 방향으로 직접 바꿔볼 수 있다는 자유도를 남겨야 한다. 그 자유도를 가능하게 하는 두 기술이 (1) AI에게 내 병원의 맥락과 생각을 정확히 전달하는 Context Engineering, (2) 첫 결과를 그대로 받지 않고 원하는 방향이 될 때까지 피드백을 반복하는 Loop Engineering이다. 단, 전달 형식은 조용한 수업이 아니라 HYROX처럼 정해진 스테이션을 완주하고 기록을 남기는 구조다.

## 2. 오프닝 와우포인트 = 스타트건

수업 시작 첫 5분, 강사가 **라이브로 치과 홈페이지 초안을 띄운다.**
- 목적: "5분 안에 누구나 이 정도 만들 수 있다"를 보여주는 wow.
- 감정: "이게 되네!"
- 이 데모는 완성본이 아니라, 이후 원장님이 맥락과 피드백으로 바꿔갈 출발점이다.
- 감정은 "강의 시작"이 아니라 HYROX 스타트건이다.

## 3. 핵심 장면 (이게 없으면 HypeProof 수업 아님)

> 원장이 AI에게 대충 시킨다 → 결과가 막연하게 나온다 → "AI가 뭘 몰랐지?"를 발견한다 → 맥락과 생각을 정확히 준다 → 결과가 달라진다 → 마음에 안 드는 부분을 다시 피드백한다 → 원하는 방향에 가까워진다.

Context Engineering은 설명으로 가르치면 안 된다. 반드시 "맥락 없이 요청한 결과"와 "맥락을 넣은 결과"를 원장님이 직접 비교해야 한다. Loop Engineering도 마찬가지로, 첫 결과를 보고 마음에 안 드는 지점을 표시한 뒤 원하는 방향으로 피드백하며 반복해야 한다.

## 4. 4시간 HYROX 운영안

| 시간 | 흐름 | 현장 활동 | 핵심 질문 | 산출물 |
|---|---|---|---|---|
| 0:00–0:15 | **START** | 5분 라이브 데모 + 코스 공개 | "이게 되네?" | 치과 홈페이지 초안 |
| 0:15–1:30 | **STATION 1: Context** | 맥락 없는 V1 → 빠진 맥락 표시 → Context Pack 작성 → V2 생성 | "AI가 무엇을 몰랐나?" | Context Pack + V1/V2 비교 |
| 1:30–3:20 | **STATION 2: Loop** | V2에서 마음에 안 드는 부분 표시 → 피드백 라운드 1/2 → Best Version 선택 | "원하는 방향까지 어떻게 다시 말할까?" | Loop Log + 최종 홈페이지 초안 |
| 3:20–4:00 | **FINISH** | 전후 비교 + 완주 기록 + 우승자 선정 | "내가 어떤 말로 결과를 바꿨나?" | Before/After + Winner Note |

클로징 문장:

> 홈페이지 하나를 보여주는 것이 아니라, 처음의 부족한 V1과 원장님이 바꿔낸 최종본을 함께 보여줍니다. HYROX 기록표처럼 "어떤 맥락을 넣었고, 몇 번의 피드백으로 어디까지 바뀌었는지"가 남습니다.

## 5. 결과물 수준

이번 범위는 홈페이지 초안과 수정 경험, 그리고 완주 기록이다. 기준 사이트는 구조와 정보 흐름을 참고하기 위한 레퍼런스로만 쓴다.

### 이번에 제외

- 내부자용 설계 해설서
- 도메인지식 확인을 커리큘럼 주연으로 내세우는 구성

### 반드시 남길 기록
- Context Pack: AI에게 준 병원 설명서
- Loop Log: 어떤 피드백을 몇 번 줬고 무엇이 바뀌었는지
- Before/After: 맥락 없는 V1과 최종본 비교
- Winner Note: 가장 선명하게 바뀐 홈페이지와 가장 좋은 수정 이유
