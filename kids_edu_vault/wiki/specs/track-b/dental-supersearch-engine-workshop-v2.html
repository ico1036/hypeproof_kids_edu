7 AI Native Assets = 검색스킬 제작 능력

7개 Asset은 “좋은 검색엔진을 만드는 사고 루프”다

미션카드는 필요 없다. 참가자는 하나의 슈퍼서치엔진을 만들면서, 어떻게 질문을 쪼개고, 어떤 도구를 쓰고, 무엇을 걸러내고, 어떻게 원장님 검증을 반영할지 스스로 루프를 돈다.

1. 도입원장님을 이겨라: 검색엔진 챌린지
2. 탐색검색할 문제를 결정 문제로 바꿈
3. 첫 시도질문·도구·출처 필터 V1 설계
4. 개선원장님에게 깨지고 검색 규칙 수정
5. 공유병원용 검색스킬로 저장
7 Asset검색스킬 만들 때의 핵심 질문엔진에 들어가는 기능원장님에게 깨질 포인트
Intent Clarity이 검색은 무슨 결정을 돕는가? 환자설명, 구매, 콘텐츠, 내부교육 중 무엇인가?검색 목적 선택 + 성공 기준 입력“그건 검색 문제가 아니라 진료 판단이야.”
Context DesignAI가 오해하지 않게 어떤 배경을 줘야 하나? 환자군, 상황, 병원 톤, 금지표현은?Context Pack: 대상/상황/제약/톤/금지어“우리 병원은 그 표현 안 써.”
Delegation JudgmentAI에게 어디까지 시키고, 어디서 원장님 판단으로 넘길까?AI 할 일/사람 판단/금지 업무 3분류“이건 AI가 결론내면 안 돼.”

검색스킬 제작 루프

참가자가 진짜 고민하게 될 것들

슈퍼서치엔진을 잘 만들려면 단순히 검색어를 넣는 게 아니라, 검색 전략·도구 선택·필터링·검증·표현까지 설계해야 한다. 여기서 7 Assets가 전부 작동한다.

1. 질문 쪼개기

  • 큰 질문을 검색 가능한 작은 질문으로 분해
  • 한국어/영어/전문용어 쿼리 변환
  • 결론형 질문 vs 근거형 질문 구분

2. 도구 고르기

  • 웹검색: 넓게 훑기
  • 공식 사이트/학회: 기준 확인
  • 논문/리뷰: 근거 확인
  • 제조사 문서: 제품/장비 확인

3. 출처 필터링

  • 공식/학회/대학병원 우선
  • 광고성 블로그/유튜브는 보류
  • 날짜, 이해관계, 과장표현 확인

4. 원장님 질문 만들기

  • AI가 결론내지 말고 질문으로 넘김
  • “이 표현 환자에게 써도 되나요?”
  • “이 출처 우리 병원 기준에 맞나요?”

5. 깨진 이유 반영

  • 틀린 검색어 저장
  • 믿으면 안 되는 출처 저장
  • 우리 병원 금지 표현 저장

6. 재사용 규칙화

  • 다음 검색 때 자동으로 같은 필터 적용
  • 원장님 승인 출처 목록 축적
  • 환자용/내부용 출력 분리
FDE 해커톤 산출물

치과 안에서만 아는 지식이 앱에 남는다

외부 검색은 누구나 한다. 진짜 자산은 원장님과 직원만 아는 병원 맥락이 검색엔진의 규칙으로 저장되는 순간이다.

우리 병원 표현환자에게 쓰는 말투, 금지어, 부드러운 설명 방식
원장님 판정 기준PASS / 더 확인 / 위험을 가르는 내부 기준
자주 받는 질문환자가 실제로 묻는 질문과 직원이 막히는 지점
신뢰 출처 목록원장님이 인정하는 학회·대학병원·제조사·문서
해커톤 결과물 = 검색 웹앱 + 병원 내부 규칙 + 원장님 검증 로그. 즉, 체험이 아니라 작은 내부 솔루션.

수업 루프

직원이 도전하고, 원장님이 깨주고, 그 깨짐이 시스템으로 남는 5단계.

1
직원 질문Intent Clarity — 궁금증을 결정 문제로 바꾼다.
2
검색엔진 생성Context Design — 상황·기준·금지조건을 넣는다.
3
1차 판단Delegation — AI 검색과 인간 판단을 나눈다.
4
원장님을 이겨라Verification — 깨지면서 검증 기준을 배운다.
5
깨진 이유 저장Ownership — 병원 지식 시스템으로 남긴다.
