# HypeProof Studio Game Skill Pack v1

## 0. 기준: 봉호 커리큘럼 구현

이 스킬팩의 목적은 Studio 자체를 앞세우는 것이 아니다. [[curriculum-core]]와 [[specs/skins/kids/skin-kids]]에 있는 봉호 커리큘럼을 소프트웨어 흐름으로 구현하는 것이다.

따라서 모든 기능은 아래 순서를 강제해야 한다.

1. AI 지휘관 선언
2. 자기 캐릭터/세계/미션 탐색
3. 첫 결과 V1 생성
4. 결과 해부와 질문 수정
5. V2/V3 개선
6. QR/URL/발표 카드로 증거 수여


## 결정

SK바이오팜 가족 AI 게임 창작 수업은 봉호 커리큘럼을 본체로 두고 [[hypeproof-studio]]로 구현한다.

Claude Code/Cline 같은 범용툴을 그대로 노출하는 방식보다, HypeProof Studio 안에 게임 제작에 특화된 스킬·룰·프롬프트를 미리 깔아둔 교육 OS로 운영하는 것이 맞다.

## 이유

- 대상이 초3~초6 가족 수업이므로 범용 코딩툴은 진입장벽과 실패율이 높다.
- HypeProof Studio가 있어야 수업 흐름, 안전장치, 결과물 저장, 성장 리포트 데이터 수집을 통제할 수 있다.
- 상품 정체성은 “AI 코딩툴 사용법”이 아니라 “게임 제작을 통한 7 AI Native Assets 훈련”이다.
- 게임 제작은 자유도가 너무 높기 때문에, 사전 룰과 프롬프트 scaffolding이 없으면 4시간 안에 완성 보장이 어렵다.


## 봉호 커리큘럼을 Studio 룰로 변환

Studio Game Skill Pack은 봉호님의 커리큘럼 코어를 소프트웨어 룰로 박아 넣어야 한다.

| 봉호 원칙 | Studio 구현 |
|---|---|
| 지시받는 사람 → AI를 지시하는 사람 | 첫 화면 카피: “오늘은 네가 AI 지휘관” |
| 자기 것에서 시작 | 캐릭터/세계/미션 입력을 필수 첫 단계로 둔다 |
| 첫 결과는 개선 재료 | V1 생성 후 바로 “마음과 다른 점 찾기” 화면으로 이동 |
| 올바른 질문이 결과를 바꾼다 | 수정 프롬프트 카드와 Before/After 비교 제공 |
| 결과물을 손에 쥐고 간다 | URL/QR/발표 카드/성장 리포트 자동 생성 |
| 진행자는 대신 하지 않는다 | 코치 대시보드에 “대신 입력 금지, 질문으로 유도” 룰 표시 |

핵심은 게임 엔진보다 **교육 루프 강제**다. 봉호 커리큘럼을 구현하기 위해 Studio는 아이가 V1에서 멈추지 않고 반드시 검증→수정→공유로 지나가게 해야 한다.

## Studio가 제공해야 하는 것

### 1. Game Creation Skill

아이디어를 playable game으로 바꾸는 고정 루프.

1. 게임 목표 한 문장 만들기
2. 캐릭터/세계/규칙 입력
3. 안전한 게임 제약 적용
4. 단일 HTML 또는 Studio 템플릿 게임 생성
5. 실행/미리보기
6. 검증 질문 제시
7. 수정 요청 생성
8. V2/V3 저장
9. 발표 카드 생성

### 2. Rule Pack

모든 생성에 기본 적용되는 규칙.

- 초등학생이 3분 안에 이해할 수 있어야 한다.
- 무섭거나 폭력적이거나 죽음/HP 소거 중심 표현은 피한다.
- 밝고 안전한 협력형/탐험형/창작형 톤을 우선한다.
- 게임 목표는 화면에 명확히 보인다.
- 키보드/마우스 조작은 단순해야 한다.
- 실패해도 다시 시도할 수 있어야 한다.
- 코드/에러 메시지는 아이에게 직접 노출하지 않는다.
- 결과물은 저장/공유/재실행 가능해야 한다.

### 3. Prompt Pack

#### System Prompt — Game Builder

```text
너는 HypeProof Studio의 어린이 게임 제작 코치다.
목표는 아이가 말한 상상과 규칙을 안전하고 간단한 playable web game으로 바꾸는 것이다.
코드를 보여주는 것이 목적이 아니라, 아이가 자기 게임을 만들고 검증하고 개선하게 돕는 것이 목적이다.

항상 지킬 것:
- 초등학생이 3분 안에 이해할 수 있는 게임으로 만든다.
- 무섭거나 폭력적이거나 죽음/체력 소거 중심의 메커닉은 피한다.
- 밝고 안전한 협력형/탐험형/창작형 게임을 우선한다.
- 첫 화면에 목표와 조작법을 짧게 보여준다.
- 결과물은 즉시 실행 가능해야 한다.
- 아이가 직접 판단할 수 있도록 수정 질문을 남긴다.
```

#### Initial Game Prompt

```text
다음 기획을 바탕으로 초등학생용 간단한 웹 게임 V1을 만들어줘.

게임 목표: {{goal}}
주인공: {{character}}
세계: {{world}}
성공 조건: {{win_condition}}
방해 요소: {{obstacle}}
분위기: 밝고 안전하고 재미있게
연령대: {{grade_band}}

요구사항:
- 3분 안에 이해 가능
- 조작법 단순
- 화면에 목표 표시
- 바로 실행 가능한 형태
- 다음에 고칠 수 있는 구조
```

#### Verification Prompt

```text
이 게임을 아이가 직접 플레이한 뒤 확인할 질문을 만들어줘.
질문은 5개 이하로 하고, 아이가 쉽게 답할 수 있게 해줘.
검증 기준은 재미, 난이도, 목표의 명확성, 내 아이디어 반영, 고치고 싶은 점이다.
```

#### Revision Prompt

```text
아이의 피드백을 반영해 게임을 V2로 개선해줘.

아이 피드백: {{child_feedback}}
부모/코치 피드백: {{coach_feedback}}
반드시 유지할 것: {{must_keep}}
바꿀 것: {{change_request}}

수정 후 무엇이 바뀌었는지 아이 눈높이로 3줄 요약해줘.
```

### 4. Grade Mode

| 모드 | 대상 | Studio 기본값 |
|---|---|---|
| B Mode | 초3·4 | 캐릭터/세계관/간단한 미션 중심, 선택지 많게, 타이핑 적게 |
| A Mode | 초5·6 | 규칙/점수/난이도/검증 중심, 수정 루프 강조 |

### 5. Coach Dashboard

코치가 봐야 할 신호.

- 아직 목표 문장이 없는 팀
- V1 생성 실패 팀
- 플레이 검증을 하지 않고 넘어간 팀
- 수정 요청 없이 끝내려는 팀
- 부모가 대신 입력하는 팀
- 발표 카드 미작성 팀

### 6. Growth Report Data

수업 후 7 Assets 리포트를 만들기 위해 저장할 데이터.

| Asset | 저장 데이터 |
|---|---|
| Intent Clarity | 최초 목표 문장 |
| Context Design | 캐릭터/세계/규칙 입력량과 변화 |
| Delegation Judgment | AI/아이/부모 역할 체크 |
| Iteration Reflex | V1/V2/V3 버전 수와 수정 요청 |
| Verification Reflex | 플레이 후 검증 메모 |
| Taste | 아이가 선택/거절/수정한 이유 |
| Ownership | 발표 카드와 다음 버전 아이디어 |

## 핵심 리스크

Studio가 “범용툴보다 못한 자체툴”처럼 보이면 안 된다. 따라서 Studio의 목표는 범용툴 경쟁이 아니라, 아이/가족 수업의 완성률을 높이는 guided environment다.



## 메타게임 구조 — 게임기 안에서 게임을 만드는 게임

HypeProof Studio는 단순 제작 도구가 아니라 **커다란 게임기**처럼 설계한다. 아이는 Studio 안에서 “게임을 만드는 게임”을 플레이한다.

구조:

```text
HypeProof Studio = 게임기 / 메타게임 OS
        ↓
아이의 프로젝트 = 게임 속 퀘스트
        ↓
AI와 대화 = 조작/전투/협력
        ↓
V1 생성 = 첫 스테이지 클리어
        ↓
플레이테스트 = 보스전/검증 미션
        ↓
수정 요청 = 레벨업 행동
        ↓
발표/QR = 엔딩 보상
```

이 구조에서는 7 Assets를 성적표처럼 노출하지 않는다. 대신 게임적 성취로 보이게 한다.

| 내부 7 Assets | 아이가 보는 게임적 표현 |
|---|---|
| Intent Clarity | 지휘관 선언 완료 |
| Context Design | 세계 설계자 뱃지 |
| Delegation Judgment | AI 동료 지휘 성공 |
| Iteration Reflex | 첫 수정 성공 / 레벨업 |
| Verification Reflex | 플레이테스트 클리어 |
| Taste | 내 스타일 적용 |
| Ownership | 내 게임 출시 / 다음 버전 해금 |

핵심은 아이가 “평가받았다”고 느끼는 것이 아니라, **게임을 만들면서 스킬을 얻었다**고 느끼게 하는 것이다.

## 평가 프레임 금지 — 봉호 커리큘럼 우선

주의: Studio 내부에 7 Assets 관련 데이터를 남기더라도, 이를 아이에게 점수표처럼 노출하거나 성적표처럼 표현하면 안 된다. 이는 봉호 커리큘럼의 핵심인 몰입, 해방감, “내가 AI를 지휘했다”는 경험을 해칠 수 있다.

따라서 현재 기준은 다음과 같다.

- 아이에게는 평가하지 않는다.
- 부모에게도 점수표를 주지 않는다.
- Studio는 과정 흔적을 조용히 기록한다.
- 코치는 그 흔적을 바탕으로 “무엇을 만들었고, 무엇을 고쳤고, 다음에 무엇을 해볼 수 있는지”를 서술한다.
- 0/1/2 같은 루브릭은 봉호님 확인 전까지 제품/문서 기준에서 사용하지 않는다.

정확한 표현:

> 평가는 아이를 재는 것이 아니라, 아이가 AI를 지휘한 흔적을 보존하고 따뜻하게 번역하는 것이다.

## 성공 기준

- 4시간 안에 모든 가족이 실행 가능한 게임을 만든다.
- 모든 팀이 최소 1회 이상 검증과 수정 루프를 경험한다.
- 코치가 미완성/막힘 팀을 실시간으로 파악할 수 있다.
- 수업 후 7 Assets 리포트 초안이 자동 생성된다.
