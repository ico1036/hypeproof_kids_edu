# SK바이오팜 임직원 가족 AI 게임 창작 워크숍 — 내부 설계안 v1

> 내부 문서. 고객 노출 금지 항목: 7 asset 명칭, HypeProof Essence, 내부 매핑 표.
> 고객에게는 "두 가지 힘"(생각을 전달하는 힘 / 만들고 확인하고 고치는 힘)만 노출한다.

## 설계 원칙 (5줄)

1. **설명보다 와우가 먼저.** 첫 15분 안에 "AI가 만들고 있네"를 눈으로 보게 한다. 이론은 마지막 10분에만.
2. **겉은 게임, 본질은 루프.** 상상 → 구조화(기획카드) → 제작(AI) → 검증(테스트) → 개선(다시 말하기) → 발표.
3. **고객용 레슨은 2개만.** Context Engineering = "AI가 알아듣게 생각을 꺼내 말하기", Feedback Loop = "해보고, 찾고, 다시 말해서 고치기". 나머지 5개 asset은 활동 속에 숨긴다.
4. **부모는 구경꾼이 아니라 역할이 있다.** 인터뷰어(저학년) / QA·퍼블리셔(고학년). 부모의 와우 = "우리 애가 이런 생각을 하네".
5. **한 번에 하나만 고친다.** "더 재밌게 해줘"는 금지어. 구체적으로 말해야 결과가 바뀐다는 걸 몸으로 느끼게 한다.

## 1. 와우포인트 7

| # | 장면 | 발생 시점 | 누구의 와우 | 내부 의도 |
|---|------|----------|------------|----------|
| W1 | **"3분 만에 게임이 생겼다"** — 아이가 외친 한 문장("고양이가 떡볶이 피하는 게임!")을 진행자가 그대로 입력, 3분 뒤 큰 화면에서 플레이. 외친 아이가 첫 플레이어. | 오프닝 0:00–0:08 | 아이+부모 동시 | 개발은 AI가 한다는 세계관 주입. 동기 점화. |
| W2 | **"같은 말, 다른 게임"** — "점프 게임 만들어줘"(모호) vs "주인공·장소·이기는 조건·방해물"이 들어간 문장(구조화)을 나란히 실행. 모호한 쪽은 시시하고 엉뚱하게 나옴. | 오프닝 0:08–0:15 | 부모 (교육 가치 각인) | Context Engineering의 존재 증명. "말을 다르게 하니 결과가 바뀌네." |
| W3 | **"내 카드가 진짜 게임이 된다"** — 종이에 쓴 기획카드를 읽어주자 우리 가족만의 게임 V1이 우리 노트북에 뜬다. | V1 빌드 0:35–1:05 | 아이 | 소유감. 내가 정하면 세상이 바뀐다. |
| W4 | **"버그가 보물이 된다"** — 옆 가족과 노트북을 바꿔 서로의 게임을 테스트. 이상한 점을 찾으면 '보물 사냥꾼' 스티커. 버그 발견이 박수받는 분위기. | 테스트 1:05–1:25 | 아이 (실패 재해석) | Verification reflex. 결과 확인은 부끄러운 게 아니라 능력. |
| W5 | **"내가 말한 대로 30초 만에 바뀐다"** — "장애물 속도를 절반으로 해줘" → 눈앞에서 게임이 패치됨. 개선 전/후를 가족이 비교 플레이. | V2 루프 1:25–1:55 | 아이+부모 | Feedback Loop의 본체. 되먹임이 즉각 보상으로 돌아옴. |
| W6 | **"기획자 인터뷰 무대"** — 발표에서 아이가 학생이 아니라 게임 기획자로 소개됨. "처음엔 ___였는데 제가 ___라고 말해서 ___로 바뀌었어요. 다음 버전에는 ___를 넣을 거예요." | 발표 3:10–3:45 | 부모 (정체성 전환 목격) | Ownership + 구조화된 전달. 개선 서사를 본인 입으로 말하게 함 = 체화. |
| W7 | **"QR로 게임이 집에 간다"** — 발표 직후 가족별 QR 배포. 그 자리에서 부모 폰으로 서로의 게임을 플레이. "오늘 밤 할머니께 보내세요." | 클로징 3:45–4:00 | 가족 전체 | 산출물이 소멸하지 않음. 워크숍 밖으로 루프가 이어짐(재방문·바이럴 동선). |

W1·W2가 당근(미끼), W3·W5가 본체험, W6·W7이 각인. 말로 하는 정리는 W6과 W7 사이 10분뿐.

## 2. 4시간 상세 커리큘럼

총 240분 = 메인 120분 + 쿠션 60분 + 회고·발표 60분.
좌석: 가족(부모+아이) 1팀 = 노트북 1대. 보조 강사 1인당 2~3가족 전담.

### 입장 전 세팅 (–0:10)
- 큰 화면에 샘플 게임 자동 플레이 + "지은이: ○○○" 표기 노출.
- 각 테이블: 기획카드, 발견카드, 보물 스티커, 이름표("게임 기획자 ___").
- 데모 실패 대비: 사전 빌드 캐시 1개, 백업 핫스팟.

### BLOCK 1 — 와우 오프닝 (0:00–0:15)

| 항목 | 내용 |
|---|---|
| 활동 | 라이브 빌드 데모(W1) + 같은 말 다른 게임 데모(W2) |
| 진행자 멘트 | "오늘 설명은 안 합니다. 바로 만듭니다. 게임에 꼭 나왔으면 하는 거 하나만 외쳐볼까?" → (빌드 중) "지금 코드는 누가 쓰고 있죠? AI예요. 우리는 뭘 했죠? **말**을 했어요." → (W2 후) "같은 AI인데 왜 결과가 다를까요? 오늘 배울 건 코딩이 아니라 **AI가 알아듣게 말하는 법**입니다." |
| 아이 행동 | 아이디어 외치기, 데모 게임 첫 플레이 |
| 부모 행동 | 관찰 (개입 없음) |
| 산출물 | 데모 게임 1개 (큰 화면) |
| 숨은 의도 | 동기 점화 + Intent clarity/Context design의 존재 증명. "AI가 만든다"를 말이 아니라 눈으로 합의. |

W2 데모용 프롬프트 페어 (사전 준비, 그대로 사용):
- 모호: "점프 게임 만들어줘"
- 구조화: "토끼가 주인공이고, 밤하늘 구름 위에서, 별 10개를 모으면 이기는 점프 게임. 까마귀가 방해하고, 구름에서 떨어지면 다시 시작."
- 운영: 모호 버전은 사전 빌드 캐시로 즉시 표시, 구조화 버전만 라이브 실행 → 대기시간 1회로 압축.

### BLOCK 2 — 게임 설계 카드 (0:15–0:35) ← Context Engineering 레슨 본체

| 항목 | 내용 |
|---|---|
| 활동 | 종이 기획카드 작성. 노트북은 아직 닫아 둠. 저학년: 말풍선 5칸(주인공/어디서/뭐 하면 이겨/방해물/우리만의 특별한 것). 고학년: +규칙·점수·지는 조건·난이도 |
| 진행자 멘트 | "AI는 똑똑하지만 여러분 머릿속은 못 봐요. 머릿속에 있는 걸 **카드에 꺼내 놔야** AI가 만들 수 있어요. 칸이 비면 AI가 멋대로 정합니다 — 아까 점프 게임처럼요." |
| 아이 행동 | 결정권자. 모든 칸을 본인이 정한다 |
| 부모 행동 | **인터뷰어**: 질문만 가능("그래서 주인공이 뭘 하면 이기는 거야?"), 답 정하기 금지. 보조 강사가 부모 역할 카드를 미리 배부 |
| 산출물 | 기획카드 1장 (이후 모든 블록의 기준 문서) |
| 숨은 의도 | 생각의 구조화 = Context Engineering. 내부적으로 intent clarity + context design + taste("좋은 게임이 뭔지"를 먼저 정함). 부모에겐 '질문으로 생각을 꺼내는 법' 시연. |

### BLOCK 3 — V1 빌드 (0:35–1:05)

| 항목 | 내용 |
|---|---|
| 활동 | 기획카드를 HypeProof Studio에 말하기/입력하기. 규칙: **카드에 있는 것만, 카드 순서대로.** 빌드 대기 시간엔 "AI가 뭘 만들고 있을지" 예측 그림/메모 |
| 진행자 멘트 | "카드를 그대로 읽어주세요. 그리고 기다리는 동안 맞혀 보세요 — AI가 어떻게 만들었을까?" / (1차 결과 후) "이상하게 나왔나요? AI 잘못일까요, **카드에 안 적은 우리** 잘못일까요? 카드에 한 줄 추가하고 다시 말해 보세요." |
| 아이 행동 | 저학년: 구술 (부모가 받아 입력), 고학년: 직접 타이핑 |
| 부모 행동 | 저학년: 타이피스트(아이 말을 고치지 않고 그대로 입력), 고학년: 옆에서 카드 대조 체크 |
| 산출물 | 플레이 가능한 V1 + 카드와 결과의 차이 메모 1줄 |
| 숨은 의도 | 위임 감각(만드는 건 AI, 정하는 건 나) + W3 소유감. "예측→결과 비교"는 고학년 가설-검증의 씨앗. |

### BLOCK 4 — 테스트 & 버그 보물찾기 (1:05–1:25)

| 항목 | 내용 |
|---|---|
| 활동 | 자기 게임 5분 → 옆 가족과 노트북 교환 10분 → 발견카드 작성: 좋았던 것 1 / 이상한 것 1 / 바꾸고 싶은 것 1. 버그 발견 시 보물 스티커 |
| 진행자 멘트 | "버그를 찾은 사람이 오늘의 보물 사냥꾼입니다. 게임이 이상한 건 부끄러운 게 아니라 **V2로 가는 지도**예요. 진짜 게임 회사도 이렇게 합니다 — 테스터가 없으면 게임은 안 좋아져요." |
| 아이 행동 | 테스터. 남의 게임에서 좋은 점 1개를 반드시 먼저 말하고 버그를 말한다 |
| 부모 행동 | 서기. 아이가 말하는 발견을 카드에 기록 |
| 산출물 | 발견카드 2장 (내 게임에 대해 받은 것 + 남의 게임에 써 준 것) |
| 숨은 의도 | Verification reflex + taste(좋고 나쁨을 말로 구분). 교차 테스트는 피드백을 '공격'이 아니라 '선물'로 학습시키는 장치. |

### BLOCK 5 — V2 개선 루프 (1:25–1:55) ← Feedback Loop 레슨 본체

| 항목 | 내용 |
|---|---|
| 활동 | 발견카드에서 1개 선택 → "AI에게 뭐라고 말해야 고쳐질까?" 문장을 종이에 먼저 작성 → 실행 → 전/후 비교 플레이. 목표 2회전 |
| 진행자 멘트 | "**한 번에 하나만** 고칩니다. 그리고 '더 재밌게 해줘'는 마법이 안 통해요. '장애물 속도를 절반으로'처럼 말해야 통합니다. 고치기 전에 예언해 보세요 — 이렇게 바뀔 거다. 맞았는지 확인하는 사람이 진짜 기획자예요." |
| 아이 행동 | 고칠 것 선택, 개선 문장 작성(저학년은 구술), 전/후 비교 판정("진짜 좋아졌나?") |
| 부모 행동 | 전/후 기록 담당: "처음엔 ___ → ___라고 말함 → ___로 바뀜" 한 줄 작성 (이 한 줄이 발표 대본이 됨) |
| 산출물 | V2 게임 + 개선 전/후 기록 1~2줄 |
| 숨은 의도 | Feedback Loop 본체(iteration reflex). 개선 문장을 먼저 종이에 쓰게 하는 이유: 되는대로 말하기 방지 + AI 대기시간 활용 + 발표 자산 축적. |

### BLOCK 6 — 1부 클로징 (1:55–2:00)

진행자 멘트 (이것만, 30초):
> "여러분 오늘 코딩 한 줄도 안 했는데 게임이 두 번 좋아졌어요. 뭘 잘해서죠? **말을 잘해서요.** 쉬고 와서, 여러분 게임을 출시 버전으로 만들 겁니다."

### CUSHION — 오픈 스튜디오 (2:00–3:00)

| 시간 | 내용 |
|---|---|
| 2:00–2:15 | 간식·휴식 (화면 잠금. 아이들 과몰입 차단) |
| 2:15–2:55 | **퀘스트 카드 자유 선택**: ①소리/이펙트 ②점수판 ③보스 등장 ④스토리 인트로 ⑤쉬움/어려움 모드 ⑥비밀 요소. 뒤처진 가족은 V2 완성이 최우선 — 보조 강사가 전담 케어. 앞선 가족은 퀘스트 2~3개 |
| 2:55–3:00 | **피처 프리즈 선언** + QR 생성: "여기까지가 오늘의 출시 버전입니다. 진짜 게임 회사도 출시 전엔 멈춥니다." |

- 숨은 의도: 진도 변동성 흡수(쿠션의 본 기능), ownership 심화, 고학년은 변수 실험(난이도·점수 밸런스). 퀘스트마다 "기획카드에 한 줄 추가 → 말하기 → 확인" 동일 루프를 반복시켜 루프가 습관이 되게 함.
- 운영 노트: 쿠션이 남으면 '친구 게임 1개 더 테스트'로, 모자라면 퀘스트 1개로 축소. 이 블록만 고무줄.

### RETRO — 회고·발표 (3:00–4:00)

| 시간 | 활동 | 내용 |
|---|---|---|
| 3:00–3:10 | 발표카드 작성 | 아이 3문장: ①"제 게임은 ___ 게임입니다" ②"처음엔 ___였는데, 제가 ___라고 말해서 ___로 바뀌었어요" ③"다음 버전에는 ___를 넣을 거예요". 부모 1문장: "오늘 아이에게 배운 것 하나" |
| 3:10–3:45 | 발표회 (W6) | 가족당 90초 엄수(타이머 공개). 큰 화면 미러링 + 30초 시연. 발표 끝나면 전원 박수. 호명은 "게임 기획자 ○○○". 15가족 ≈ 25분, 20가족이면 부모 문장은 추첨 5명만 |
| 3:45–3:55 | 회고 스크립트 | 아래 §4 전문 |
| 3:55–4:00 | 클로징 (W7) | 수료증("게임 기획자 1기") + QR 보드 공개 + 단체사진. "오늘 밤 할머니께 보내세요. 지은이가 누군지 꼭 보여드리고요." |

## 3. 초3~4 / 초5~6 차별화

발달 근거 요약 (내부용, 고객 문서엔 풀어서 씀):
- **초3~4 (만 8~10, 구체적 조작기 중반)**: 추상 변수 조작이 어렵고 구체물·캐릭터 서사로 사고. 작업기억이 짧아 동시 변경은 1개가 한계. 실행기능 미성숙 → 활동 단위 10~15분 + 몸을 움직이는 전환 필요. 실패를 자기 탓으로 귀인하기 쉬움 → '버그=보물' 프레이밍 필수. 읽기·타이핑 느림 → 구술 중심.
- **초5~6 (만 10~12, 형식적 조작기 진입)**: 가설-연역 가능 → "예측→실험→확인"을 명시적으로 시킬 수 있음. 규칙·공정성 민감 → 밸런스 과제가 잘 먹힘. 메타인지 시작 → "AI가 왜 못 알아들었을까" 회고 가능. 또래 평가에 민감 → 순위 금지, 장르 어워드로 대체. 부모 개입에 반발 시작 → 부모 역할을 공식 직함으로 제도화.

| 운영 항목 | 초3~4 트랙 | 초5~6 트랙 |
|---|---|---|
| 기획카드 | 말풍선 5칸 + 그림 허용 (주인공/어디서/뭐 하면 이겨/방해물/특별한 것) | 8칸 (＋규칙, 점수, 지는 조건, 난이도) |
| 입력 방식 | 아이 구술 → 부모 타이핑 (음성입력 보조) | 아이 직접 타이핑 |
| 부모 역할 | 인터뷰어 + 타이피스트 ("그대로 입력" 원칙) | QA 디렉터·퍼블리셔 (테스트 리포트, 출시 승인 사인) |
| 개선 단위 | 1회전에 1변경, 진행자가 고를 것을 같이 좁혀줌 | 1회전에 1변경 + 사전 예측 적기 ("이러면 이렇게 될 것") |
| 개선 언어 | "고쳐줘 주문 만들기" (주문=구체적 문장) | "가설→실험→확인" 용어 그대로 사용 |
| 쿠션 퀘스트 | 캐릭터 꾸미기, 소리, 스토리 인트로 | 난이도 곡선, 점수 밸런스, 보스 패턴, 쉬움/어려움 모드 |
| 발표 | 1문장 + 시연 중심 (말 부담 최소화) | 3문장 풀버전 + 다음 버전 로드맵 |
| 시상 | 전원 보물 사냥꾼 스티커 | 장르 어워드 (가장 무서운 게임상, 가장 웃긴 게임상, 가장 어려운 게임상 등 전 가족 1개씩) |
| 진행자 언어 | "주문", "보물", "마법" | "기획", "테스트", "버전", "출시" |
| 시간 운영 | 블록 내 10분 단위 마이크로 전환, 교차 테스트 때 자리 이동으로 신체 활동 | 블록 단위 그대로, 몰입 끊지 않기 |

두 트랙을 같은 시간대에 한 공간에서 운영할 경우: 구역 분리 + 보조 강사 트랙 전담 배치. 오프닝/회고는 공통, BLOCK 2~5의 멘트만 트랙별로 갈라짐.

## 4. 회고·발표 스크립트 (3:45–3:55, 전문)

발표 직후, 진행자가 무대에서. 슬라이드 없음.

> "딱 세 가지만 묻고 끝낼게요.
>
> 오늘 코드를 한 줄이라도 쓴 사람, 손? (아무도 없음) 그런데 지금 이 방에 게임이 몇 개 생겼죠? 열다섯 개. (※당일 가족 수로 치환)
>
> 만든 건 AI예요. 그럼 여러분은 뭘 한 거죠?
> **무엇을 만들지 정했어요.** — 카드에 적었죠.
> **AI가 알아듣게 말했어요.** — 그래서 게임이 나왔죠.
> **해 보고, 이상한 걸 찾고, 다시 말해서 고쳤어요.** — 그래서 게임이 좋아졌죠.
>
> 정하기, 말하기, 고치기. 이 세 가지는 AI가 아무리 좋아져도 AI가 대신 못 합니다. 여러분 게임이니까요.
>
> 부모님들, 오늘 아이가 한 게 앞으로의 공부입니다. 답을 외우는 게 아니라, 생각을 꺼내서 전달하고, 결과를 확인하고 고치는 것. 그걸 오늘 네 시간 동안 옆에서 직접 보셨어요. 집에서 아이가 AI랑 뭔가 만들고 있으면, 오늘 하신 것처럼 딱 한 가지만 물어봐 주세요 — '그래서 어떻게 바꿔 달라고 말할 거야?'
>
> 마지막으로, 게임은 QR로 집에 갑니다. 오늘 밤 할머니께 보내 드리세요. 지은이가 누군지 꼭 보여 드리고요."

(끝. 3분 이내. 이후 수료증·사진.)

스크립트 설계 노트: ①발표에서 아이들이 이미 "내가 ___라고 말해서 바뀌었다"를 본인 입으로 말한 직후라, 진행자는 그 경험에 이름만 붙인다(체화→명명 순서). ②부모에게 주는 건 이론이 아니라 **집에서 쓸 질문 1개**. ③"정하기·말하기·고치기"는 고객용 문안에서도 동일하게 쓰는 3단어 — 워크숍 전체에서 단 한 번, 여기서만 정리한다.

    서브: 코딩 수업이 아닙니다. 아이가 AI에게 일을 시키는 법을 배웁니다.

[4] 4시간의 여정 (4단계 아이콘 타임라인)

[8] CTA 반복 + 일정/장소(사내 카페 10층) + 문의

## 7. 운영 리스크 체크 (요약)

- **AI 지연/장애**: 사전 빌드 캐시, 대기시간은 항상 "다음 문장 미리 쓰기"로 설계되어 있어 체감 최소화. 백업 핫스팟 2대.
- **콘텐츠 가드**: 폭력·기존 IP 캐릭터 요청 → "비슷하지만 우리만의 캐릭터로 바꾸자" 전환 멘트 통일. Studio 측 세이프티 프리셋 사전 점검.
- **진도 격차**: 쿠션 1시간이 흡수. 보조 강사 1인당 2~3가족, 뒤처진 가족 전담 룰.
- **부모 과개입**: 역할 카드로 제도화(질문만/타이핑만/QA만). 보조 강사의 1차 개입 멘트: "아버님, 지금은 기획자님 결정 기다리는 중입니다."
- **발표 시간 초과**: 90초 공개 타이머 + 3문장 카드 포맷이 자체 제한.
