HypeProof Studio로 구현

Studio가 본체가 아니다. 봉호 커리큘럼이 본체고, Studio는 그 흐름을 완주시키는 실행 OS다.

봉호 커리큘럼 = 교육 본체
SK 조건 = 운영 제약
Studio = 실행 OS

1. 봉호 커리큘럼 원형

평소지시받는 사람
↓
오늘내가 AI를 지시하는 사람
↓
창작내 것을 직접 만들어낸다
↓
증거결과물을 손에 쥐고 돌아간다

3. 수업의 핵심 장면

“AI가 내 생각과 다르게 만들었다”에서 시작한다.

  • 아이가 AI에게 말한다.
  • AI가 아이 생각과 다르게 만든다.
  • 아이가 “AI가 뭘 몰랐지?”를 발견한다.
  • 질문을 더 정확히 바꾼다.
  • 결과가 바뀐다.

이 장면이 없으면 HypeProof 수업이 아니다.

5. A/B반을 나누는 이유

1차 이유는 운영 제약.

  • SK가 이미 분반 의견을 요청했다.
  • 23명을 한 번에 하면 코치 밀도와 완성률이 떨어진다.
  • 초3과 초6은 타이핑·추상화·규칙 이해 차이가 크다.
A반 초5·6

규칙·미션·난이도·검증 중심

B반 초3·4

캐릭터·세계관·상상력·소유감 중심

6. Studio 구현 원칙

Studio는 봉호 코어를 강제해야 한다.

  • 첫 화면: “오늘은 네가 AI 지휘관”
  • 캐릭터·세계·미션 입력 없이는 생성 불가
  • V1 생성 후 바로 검증 화면으로 이동
  • 수정 프롬프트 카드 제공
  • 코치 대시보드: 대신 입력 금지, 질문으로 유도
  • URL/QR/발표 카드 자동 생성
